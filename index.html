What are hreflang tags and why do they matter?

    
Hreflang tags are <link> elements placed in the <head> of your HTML (or in your XML sitemap) that tell Google and other search engines which language and regional variant of a page should appear for users in different locales. Without them, a search engine seeing near-identical content in British English and American English may treat the pages as duplicates and pick one arbitrarily — often showing the wrong version in a given country's results.

    
They are an essential part of international SEO for any site serving multiple languages or regions. Implementing them correctly means users in Germany see your German pages, users in the UK see British pricing and spelling, and your translated content earns separate rankings in each market rather than competing with itself.


    
How to implement hreflang tags correctly

    
The reciprocal rule

    
The most important rule — and the one most often broken — is that hreflang annotations must be reciprocal. Every page in a language set must reference every other page in the set, including itself. If your English page references the French page but the French page does not reference the English page, Google may ignore the whole annotation cluster. This tool generates the complete tag set so you paste the same block into every language variant.


    
Self-referencing tags

    
Each language variant must include a tag pointing to itself. Omitting the self-reference is a common mistake that can confuse crawlers. The generated output above always includes a self-referential tag for each URL you enter.


    
x-default and language fallbacks

    
x-default designates the page to show when no locale tag matches the user's location or language preference. Typical candidates are an international home page, a language selector page, or your primary English version. It is optional, but recommended when you have a clear catch-all page. Check the "Include x-default" box to add it using your default URL.


    
Language and region code format

    
Use ISO 639-1 two-letter language codes combined with optional ISO 3166-1 Alpha-2 region codes, separated by a hyphen. Examples: en (English, any region), en-gb (English, UK), en-us (English, US), de (German), de-at (German, Austria), zh-cn (Chinese Simplified), zh-tw (Chinese Traditional). Google is case-insensitive for these codes, but lower-case is convention.


    
HTML vs XML sitemap implementation

    
You can implement hreflang in three ways. The HTML head method — adding <link rel="alternate" hreflang="…" href="…" /> tags — is the most common because most CMS platforms and static site generators can inject them into every page template. The XML sitemap method uses <xhtml:link> elements inside each <url> entry; it is preferable for large sites where adding head tags to every page is impractical. Both methods have equal weight with Google. This tool generates both so you can choose whichever suits your tech stack.


    
Common hreflang mistakes to avoid

    
    
      
  • Non-reciprocal references — if page A points to page B, page B must point back to page A. Always paste the complete tag block into every variant.
    • 
      
  • Wrong language codes — using en-uk instead of en-gb, or zh instead of zh-cn / zh-tw, causes the tag to be silently ignored.
    • 
      
  • Relative URLs — hreflang values must be absolute URLs including the scheme (https://). Relative paths are not valid.
    • 
      
  • Inconsistent canonicals — the URL in your hreflang tag must exactly match the canonical URL of that page. Trailing-slash mismatches or HTTP/HTTPS mismatches break the link.
    • 
      
  • Missing self-reference — every page must reference itself in the set, even if it feels redundant.

Frequently asked questions

    
What is an hreflang tag?

    
An HTML link element or XML sitemap attribute that signals the language and regional variant of a page to search engines, preventing duplicate-content issues and ensuring the right version appears for users in each locale.

    
Do I need hreflang if I only have one language?

    
Only if you have region-specific variants (e.g. separate pages for US and UK audiences). If you truly have a single page for all language speakers, hreflang is not needed.

    
Does hreflang affect rankings?

    
Not directly. It does not boost your rankings but it prevents the wrong language version appearing in search results and stops near-duplicate translated pages from competing with each other, which protects your rankings.

How to Use the Hreflang Tag Generator

      
The Hreflang Tag Generator creates paste-ready HTML hreflang link tags and XML sitemap entries for international and multilingual SEO. Hreflang signals tell Google which language and regional version of a page to show to users in different countries and languages.

      
Add your page variants by specifying the URL, language code (ISO 639-1, e.g. 'en'), and optional country code (ISO 3166-1 alpha-2, e.g. 'GB'). The generator produces the correct HTML link tags and XML sitemap format for all variants, including the required x-default tag.

      
The most common hreflang mistake is failing to implement return links: every variant must reference every other variant, including itself. If page A in English references page B in French, page B must also reference page A. One-directional hreflang is invalid and may cause the whole set to be ignored by Google.

Frequently Asked Questions

      

        
What is hreflang and when do I need it?

        
Hreflang is an HTML attribute that tells Google which language and region a page is intended for, and points to alternate versions for other languages/regions. You need it when: you have the same content in multiple languages, you have region-specific content (e.g. en-US vs en-GB), or you're serving different prices/products by country.

      

      

        
What is the x-default hreflang tag?

        
The x-default tag designates the fallback page for users who don't match any specific language/region variant. It's typically the international homepage or the primary language version. Google serves this page to users in countries not explicitly targeted by other hreflang tags. It should always be included in your hreflang set.

      

      

        
Can hreflang be implemented in HTTP headers instead of HTML?

        
Yes. For non-HTML content (PDFs) or if you prefer server-level implementation, you can add hreflang via HTTP Link headers. The syntax is: Link: ; rel='alternate'; hreflang='en'. This is less common than HTML implementation but equally valid. Avoid duplicating hreflang in both HTML and HTTP headers for the same page.

      

      

        
Should I use hreflang for pages with different currency but same language?

        
Yes. If you have an English page for UK visitors (GBP prices) and an English page for US visitors (USD prices), use hreflang='en-gb' and hreflang='en-us' to ensure Google shows the right version to each audience. Without hreflang, Google may show a US visitor the UK-priced page or vice versa.

      

      

        
How do I confirm hreflang is working correctly?

        
Use Google Search Console: go to Index > Coverage and check for hreflang errors. The International Targeting report shows configured hreflang tags. Use Google's URL Inspection tool to see which alternate pages Google has found. Our Hreflang Checker tool fetches a live URL and validates all hreflang annotations including return links.
